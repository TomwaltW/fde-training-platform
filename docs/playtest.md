# 本地试玩(L1,备案之前)

对应方案 6.1 的 L1 和附录 E 第 4–5 天:找 5 个人玩一局——**2 位在岗的交付或售前,3 位想转岗的**——看能不能玩完、卡在哪、玩完的原话是什么。

方案写这一步的时候还没有引擎,用的是"改良版单提示词",其中两三位由你在微信里亲自扮演周总。现在引擎已经有了,试玩直接用**真引擎**:网页跑 live 模式(闸门、演员、裁判、复盘都走 `config/models.yaml` 的模型),跑在你自己的电脑上。单提示词版会放水、泄题,真引擎有导演和守卫兜着(方案 3.3.5),所以这 5 局既回答 L1 的问题,也能直接拿去做标定(方案 3.4.4 的"内测 10 份")。

备案下来之前不公开部署(第 2 节)。

---

## 1. 在本机跑起来

### 1.1 准备

仓库根目录的 `.env` 里填好 `DASHSCOPE_API_KEY`、`DEEPSEEK_API_KEY`(见 `.env.example`),再加一行 `ADMIN_EMAILS=你的邮箱`(也可以每次写在命令前面)。

```bash
pnpm playtest --dry-run      # 只检查、打印,不启动
pnpm playtest                # 检查通过后启动网页,Ctrl-C 结束
pnpm playtest --offline      # 不调模型,只彩排流程(登录、发邀请码、导出)
```

**不要直接用 `pnpm dev:web`。** Next.js 只读 `apps/web` 下的 `.env`,不读仓库根目录的 `.env`:Key 写在根目录时,网页会悄悄退回离线模式(关键词闸门 + 模板台词),试玩者玩到的是假的周总,一场试玩就白约了。`pnpm playtest` 是 `pnpm dev:web` 外面很薄的一层,只做这几件事:

| | `pnpm playtest` 做的事 | 为什么 |
|---|---|---|
| 环境变量 | 先读仓库根目录的 `.env`(命令行上临时给的变量优先,不会被覆盖) | 和 `pnpm play`、`pnpm calibrate --live` 读同一份 Key |
| 引擎 | 写死 `FDE_ENGINE_MODE=live`;按 `models.yaml` 逐个环节查 Key,缺哪个就点名哪个、不启动 | 只有百炼 Key 没有 DeepSeek Key 时,网页照样进 live 模式,能玩,收工时裁判却失败 |
| 管理员 | 没有 `ADMIN_EMAILS` 不启动 | 没有管理员就进不了 `/admin`,发不了邀请码 |
| 登录 | 没配 `SMTP_URL` 时打开 `FDE_DEV_LOGIN_CODES=1`(验证码直接显示在登录页上),并提醒只能本机用 | 本机没有发信,不这样谁都登录不了 |
| 监听地址 | 只监听 `127.0.0.1:3000`(`pnpm dev:web` 监听所有网卡) | 验证码显示在页面上时,同一个 Wi-Fi 里的人都能用管理员邮箱登录 |
| 存储 | 把内存库路径写成绝对路径传给网页,并打印出来 | `pnpm session:export` 读的是同一个文件(第 4 节) |

`--offline` 只用来彩排流程。离线对局是模板台词,不算 L1 试玩,也不要拿去标定(`session:export --list` 里"模型调用"一列是"无"的就是离线局)。

### 1.2 开局前

1. 自己先彩排一遍:`pnpm playtest --offline`,走通登录 → 生成邀请码 → 用另一个邮箱登录 → 开局 → 收工 → 导出。
2. 再用 live 模式自己认真玩一局,确认模型通、收工能出复盘。这局可以算进标定的"自己玩 5 份"。
3. 用管理员邮箱登录 `http://localhost:3000/login`(管理员不需要邀请码),在 `/admin` 的「生成邀请码」里给每位试玩者生成一个,备注写编号(P1–P5)。试玩者打开 `http://localhost:3000/login?invite=<邀请码>`,邀请码会自动填好,填自己的邮箱就能登录(验证码显示在页面上)。

### 1.3 跑的时候要知道的

- **每个账号每天最多开 3 局**(`FDE_DAILY_SESSION_LIMIT`)。每位试玩者用自己的邮箱,一般够;你自己要连着玩很多局时把它调大。
- 开发模式下每个页面第一次打开要现编译几秒,正式试玩前把落地页、对局页、复盘页都点开一遍。
- **收工后复盘要等 20–60 秒**(方案 2.4)。裁判模型偶尔没响应时页面会提示"请过一会儿再点一次「收工」",再点就行;连续失败三次会保存一份带说明的复盘(依赖裁判的几项没计分)。
- 对局都在 `.data/dev-store.json`(启动时打印的那个文件)里,这是唯一的一份。每天试玩完复制一份备份。
- 每次启动 `next dev`(16.3 起)都会在 `apps/web` 下生成 `AGENTS.md`、`CLAUDE.md`,和试玩无关,不要顺手提交。

## 2. 远程的试玩者怎么玩

**为什么不能直接部署**:内地服务器上,未备案的域名无法通过 80/443 正常访问,也申请不到 HTTPS 证书(`docs/deploy.md` 第 1、6 节,`docs/compliance-checklist.md` 第 1 项)。备案下来之前没有公开地址可发;`docs/deploy.md` 第 6 节的 SSH 隧道只适合你自己测服务器,不适合发给试玩者。所以 W0 的试玩都跑在你的电脑上,区别只是试玩者怎么碰到它。

| 方式 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| **当面** | 试玩者坐在你的电脑前玩,你坐在旁边看 | 观察最完整(停顿、皱眉、回头看资料都看得到);什么都不用暴露 | 要约时间地点;别人的键盘和输入法不顺手;你在旁边容易忍不住提示 |
| **腾讯会议:共享屏幕 + 远程控制** | 你共享浏览器窗口,试玩者在会议里申请远程控制,你同意 | 网页仍然只在你本机,不暴露任何端口;你看到的就是他看到的;征得同意后可以录屏 | 有延迟;试玩者打字走的是**你电脑上的输入法**(他敲拼音、你的输入法出字)【待确认】;免费版的时长限制【待确认】;共享前关掉别的窗口,最好用单独的浏览器用户 |
| **临时隧道** | 用 cloudflared、ngrok 或国内的内网穿透把本机端口映射到一个临时网址,发给试玩者 | 试玩者用自己的电脑或手机、按自己的节奏玩,最接近真实使用 | 见下 |

**W0 这 5 位,建议当面或腾讯会议。** 方案 6.1 说信号最强的是"亲眼看到真人在哪一句话上犹豫、在哪里想放弃",这两种方式都能看到;隧道看不到。

隧道的代价,决定用之前逐条过一遍:

1. **登录**:`pnpm playtest` 没配发信时验证码直接显示在页面上,拿到网址的人可以登录任何已注册的账号:试玩者的,以及不需要邀请码的管理员邮箱。用隧道就必须先配好 `SMTP_URL`(`docs/deploy.md` 第 5.3 节),让验证码走邮件;这时 `pnpm playtest` 不会打开回显。隧道客户端从本机连 `127.0.0.1:3000`,只监听本机不影响隧道。
2. **开发服务器**:我读了 Next.js 16.3.8 的源码(`next/dist/server/lib/router-utils/block-cross-site-dev.js`):从 localhost 以外的域名访问时,带 Origin 的 `/_next/*` 开发资源请求(至少热更新的 WebSocket)会被 403 拦下,除非在 `next.config.ts` 里加 `allowedDevOrigins`。页面在这种情况下能不能完整用下来,我没有实测【待确认】;稳妥的做法是改用生产构建(`pnpm build:web` 后启动 standalone 产物),那就不在 `pnpm playtest` 的范围内了。
3. **合规**:备案和生成式 AI 服务登记之前,通过隧道对外提供一个能用的地址是否合规【待确认】(和 `docs/compliance-checklist.md` 第 1、2 项的待确认是同一个问题)。国内的内网穿透服务一般要实名,能不能用自定义域名、会不会被拦【待确认】;境外隧道服务在内地的连通性和速度【待确认】。
4. **用完就关**:只在约好的时间段开,结束后立刻关掉隧道。

## 3. 每局怎么主持

### 3.1 开局前(每位都说同样的话)

- 说清楚数据怎么用,征得同意:"对话会保存下来,用来改评分和角色;可能会收进代码仓库(不带你的邮箱)。不想被收录直接说。"
- 只交代一句:"这是一个模拟的客户现场,你是去做调研的 FDE。我不会提示,遇到问题就当你真的在现场。"其余交给场景自己的开场。不要讲机制、不要讲怎么拿高分。
- 当面的话坐在侧后方,不要盯着屏幕念出声。

### 3.2 玩的时候看什么

只看、只记,不帮忙。记下是用户第几次发言、当时的原话;之后在导出的 `transcript.md` 里按编号找回来(U12 是用户第 12 句,N8 是角色第 8 句),改角色卡和提示词时引用编号。

| 看什么 | 记什么 |
|---|---|
| **犹豫点** | 停下来超过半分钟、删了重写、回头翻资料、问你"我该干嘛"的地方:第几句、前一句角色说了什么 |
| **放弃点** | 想放弃或真的提前收工的地方:在哪个阶段、第几句、他怎么说的 |
| 开局速度 | 从看到开场到说出第一句话用了多久(方案 5.2 W4 的验收线是 60 秒以内) |
| 怎么调研 | 有没有主动换人、去现场、看资料;有没有早早报价、承诺 |
| 模型的毛病 | 角色出戏、说了不该知道的事、编了数字、前后矛盾:记下编号,之后改提示词和守卫用 |
| **有没有主动问"什么时候能正式玩"** | 原话。"上线了告诉我""还有别的场景吗"也算;你问出来的不算 |

最后一行就是方案 6.3 第一关的 L1 信号:**5 人里至少 2 人主动问 = 过;1 人 = 修;0 人 = 不过**。不过的含义是问题在定位或说法,不在引擎(方案 6.3)。

### 3.3 收工之后:只问三个问题

等试玩者看完复盘,按顺序问,逐字记原话,不追问、不解释:

1. **哪里最像真的?**
2. **哪里想放弃?**
3. **完整版你愿意付多少钱?**

问完再聊别的。有人在问之前就自己说了"什么时候能正式玩",记进上面那一格。

### 3.4 记录表

每位一行。记录放在仓库外面,用编号不用姓名:

| 编号 | 背景 | 方式 | 对局 id | 用时 | 收工了吗 | 总分 | 犹豫点 | 放弃点 | 三个问题的原话 | 主动问正式版? | 愿付 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| P1 | 在岗售前 | 当面 | | | | | U5:…… | | 1. …… 2. …… 3. …… | 是/否(原话) | |

对局 id、用时、总分从 `pnpm session:export --list` 抄(下一节)。5 局都玩完后,按附录 E 第 7 天对照方案 6.3 第一关写半页结论。

## 4. 玩完之后:导出对局,建标定用例

```bash
pnpm session:export --list                                   # 所有对局,新的在前
pnpm session:export --id <对局 id> --calibrate beta-01       # 建标定用例(同 pnpm calibrate --init)
pnpm session:export --id <对局 id> --out /tmp/beta-01.json    # 只导出 { state } 文件
```

- `--list` 的列:对局 id、场景、状态(已收工 / 进行中及阶段)、轮数(用户发言次数)、开始和结束时间(北京时间)、总分(没出复盘是"—")、模型调用次数和花费、账号(脱敏成 `a***@example.com`)。按账号和开始时间对上记录表里的人。
- `--calibrate` 用的是和 `pnpm calibrate --init` 同一段代码,生成 `session.json`、待填的 `human.yaml`、`transcript.md`。命名:外部试玩者的局算方案 3.4.4 的"内测 10 份",叫 `beta-01`……;你自己玩的算"自己玩 5 份",叫 `self-01-good`……。没收工的局也可以建(方案说不要只挑玩完的),工具会提醒。
- **提交之前**通读 `transcript.md`:试玩者在对话里写了自己的姓名、公司或别的个人信息的,或者开局前说了不想被收录的,这局就不要提交(可以只留在本地)。导出的文件本身不带账号。
- 建好之后按 `docs/calibration.md` 第 3 节:先自己打分,把 `human.yaml` 提交了,再跑裁判。
- 库的选择和网页一样:有 `DATABASE_URL` 读 PostgreSQL,否则读内存库文件;只读,不会改库。读的是哪个库,开头那行"对局来源"会写出来。拿到的是别处复制来的 `dev-store.json` 时用 `--store-file <文件>`。
- 退出码:`0` 成功;`1` 读库或写文件失败(内存库文件坏了、连不上数据库);`2` 参数或配置错误(找不到库文件、没有这局、用例 id 不合法或已存在)。

## 5. 每局花多少钱

按方案 2.4 的用量假设(一局 30 轮;闸门每轮输入约 2,500、输出约 200 token;演员每轮输入约 3,000、输出约 180;裁判与复盘合计输入约 22,000、输出约 8,000),用当前 `config/models.yaml` 的标价算:

| 环节 | 模型 | 标价(元/百万 token,输入/输出) | 一局 |
|---|---|---|---|
| 闸门 | qwen3.7-flash | 0.2 / 0.8 | ¥0.02 |
| 演员 | qwen-plus | 0.8 / 2 | ¥0.08 |
| 裁判与复盘 | deepseek-v4-pro(复盘实际用更便宜的 qwen3.7-plus,这里全按裁判算,偏高) | 9 / 27(高峰价) | ¥0.41 |
| 合计 | | | **约 ¥0.52** |

加上重试和守卫触发的重新生成(方案按 30% 计)约 **¥0.67**;DeepSeek 空闲时段约半价,约 **¥0.40**。所以**一局约 ¥0.4–0.7**,5 位试玩者加上你自己彩排几局,总共十元以内。百炼新开通的模型各有 100 万 token 的免费额度(方案 2.4 第 7 条),闸门和演员可能完全不花钱。

这些都是方案里标了【待验证】的假设。实际花费每次模型调用都记在库里:`/admin` 的「每局成本」,或 `pnpm session:export --list` 的"模型调用"一列。5 局玩完拿实际数字回填方案 2.4。
