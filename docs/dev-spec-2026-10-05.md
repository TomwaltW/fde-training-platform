## 3. 冻结契约

以下定义在本轮内不可更改。任何任务需要改动 = 停下来报告,不要自己改。

### 3.1 数据形状

- **HTTP 接口类型**:`packages/contracts/src/api.ts`(请求体、响应体、错误码与 HTTP 状态码 `ERROR_STATUS`)。
- **持久化接口**:`packages/contracts/src/store.ts`(`Store`、`User`、`StoredSession`、`StoredReport`、`StoredFeedback`、`StoredLlmCall`、`SqlClient`、`VersionConflictError`、`SessionBusyError`)。
- **给浏览器的视图**:`packages/engine/src/view.ts`(`PublicView`、`PublicTurnResult`、`PublicArtifact`、`PublicReport`、`publicView()`、`publicTurnResult()`、`publicReport()`、`publicArtifact()`、`artifactFiles()`)。浏览器只能拿到这些类型里的字段。
- **数据库表**:`infra/db/001_init.sql`。
- **接口响应样例**:`packages/contracts/fixtures/*.json`(由 `pnpm fixtures` 用真引擎生成,前端 mock 测试直接用)。

### 3.2 调用面

**HTTP 路由**(全部在 `apps/web/app/api/**`,类型见 api.ts 注释):

| 方法 路径 | 登录 | 说明 |
|---|---|---|
| GET `/api/site` | 否 | `SiteInfo`(页脚公示) |
| GET `/api/scenarios` | 否 | `ScenariosResponse` |
| POST `/api/auth/request-code` | 否 | 新邮箱必须带有效邀请码:**此时消耗邀请码并创建用户**(consentAt=null);老用户不需要。6 位数字,10 分钟有效;同一邮箱 60 秒内只能请求一次(否则 429 rate_limited)。有 `SMTP_URL` 就发邮件;`FDE_DEV_LOGIN_CODES=1` 时在响应里返回 `devCode` 并打印到服务端日志 |
| POST `/api/auth/verify` | 否 | 成功设置 cookie `fde_session`(httpOnly、SameSite=Lax、Path=/、Max-Age 30 天;生产环境 Secure);失败 400 code_invalid |
| POST `/api/auth/logout` | 是 | 删除登录态,清 cookie |
| GET `/api/me` | 是 | `MeResponse` |
| POST `/api/me/consent` | 是 | 记录同意协议时间 |

| GET `/api/admin/stats` `/api/admin/sessions` `/api/admin/sessions/:id` `/api/admin/feedback`,POST `/api/admin/invites` | 管理员 | 非管理员 403 |

所有错误都返回 `ApiError` JSON + `ERROR_STATUS` 里的状态码;未登录 401 unauthorized。

**会话处理流程**(后端):读 `StoredSession` → `Store.withSessionLock(id, fn, 0)`(拿不到锁立即 409 session_busy)→ 调 `Engine.userTurn / act / finish` → `Store.saveSession(id, state, version)`(版本冲突也按 409 session_busy)→ 返回 `publicTurnResult()` + `publicView()`。每个场景一个 `Engine` 实例,进程内复用。

**引擎模式**:`FDE_ENGINE_MODE=offline` 用 `HeuristicGate + TemplateActor + FixtureJudge(emptyJudge) + TemplateDebrief`;`live` 用 `LlmGate/LlmActor/LlmJudge/LlmDebrief`(网关来自 `@fde/llm`,`onCall` 写 `Store.logLlmCall`)。不设时:有 `DASHSCOPE_API_KEY` 就 live,否则 offline。

**持久化选择**:有 `DATABASE_URL` 用 `createPgStore(new pg.Pool(...), { migrationsDir: <FDE_ROOT>/infra/db })`,启动时 `migrate()`;否则 `createMemoryStore({ file: FDE_MEMORY_STORE_FILE ?? <FDE_ROOT>/.data/dev-store.json })`。

### 3.3 失败面

| 场景 | 行为 |
|---|---|
| 未登录 | 401 `unauthorized` |
| 没有权限(别人的对局、非管理员访问管理接口、没拿到的资料) | 403 `forbidden`(别人的对局也可以 404 `not_found`,二选一并在测试里固定) |
| 未同意协议就开局 | 403 `consent_required` |
| 开局超过每日限额 / 验证码请求太频繁 | 429 `rate_limited` |
| 同一对局并发请求 / 版本冲突 | 409 `session_busy` |
| 对已结束的对局说话或做动作 | 409 `session_ended` |
| 请求体不合法 | 400 `bad_request` |
| 邀请码无效 | 400 `invite_invalid` |
| 验证码错误或过期 | 400 `code_invalid` |
| 模型调用失败 | 引擎内部已兜底(闸门按普通提问、演员用兜底台词、裁判按空结果);接口仍 200 |
| 其他异常 | 500 `internal`,服务端日志带堆栈,响应里不带 |

## 7. 卡住了怎么办

1. 需要的接口在契约里找不到 → **停,报告**。不要自己发明一个。
2. 需要改的文件不在自己的白名单里(包括加依赖) → **停,报告**。不要"就改一行"。

4. 验收过不了但代码逻辑自认为对 → **以验收为准**,继续改;确信是验收标准写错了 → 停,报告。
