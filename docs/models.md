# 接真模型:Key、预检、固定快照

对应方案 2.3(模型选型、「固定模型快照」)。线上四个环节(闸门、演员、裁判、复盘)用哪个模型都写在 `config/models.yaml`;这篇讲从拿到 Key 到能放心跑 `pnpm evals --live` 之间要做的事。

顺序:

1. 拿 Key(百炼、DeepSeek),`cp .env.example .env` 填进去;
2. `pnpm models:check`:Key 在不在、每个环节真请求一次能不能通、价格登记齐没有、模型名是不是固定的快照;
3. 把百炼的模型换成带日期的快照名(补价格),再跑 `pnpm evals --live` 和 `pnpm calibrate --live`。

---

## 1. 拿 Key

| 供应商 | 环境变量 | 用在 | 在哪拿 |
|---|---|---|---|
| 阿里云百炼 | `DASHSCOPE_API_KEY` | 闸门、演员、复盘 | 用阿里云账号登录百炼控制台,开通模型服务,在 API Key 管理页面创建 |
| DeepSeek | `DEEPSEEK_API_KEY` | 裁判 | 在 DeepSeek 开放平台(platform.deepseek.com)注册、充值,在 API keys 页面创建 |

- 完整的 Key 一般只在创建时显示一次,当场复制。
- 百炼的 Key 分地域。`config/models.yaml` 里的地址是 `dashscope.aliyuncs.com`(中国内地);在别的地域(如国际站)建的 Key 拿到这里会鉴权失败(401)。
- 百炼新开通的模型各有 100 万 token 的免费额度,有效期 90 天(方案 2.4、附录 F 的 [S8]),预检和内测期间的回归评测基本都在额度内。

```bash
cp .env.example .env
# 编辑 .env,填 DASHSCOPE_API_KEY 和 DEEPSEEK_API_KEY(等号后面直接写 Key,不要引号和空格)
```

`.env` 在 `.gitignore` 里,不会被提交。命令行工具(`pnpm play`、`pnpm evals --live`、`pnpm calibrate --live`、`pnpm models:check`)都会自动读仓库根目录的 `.env`;已经在环境里设了的变量以环境为准,`.env` 不覆盖。

---

## 2. 预检:`pnpm models:check`

Key 填好后第一个跑的命令。真模型出问题时,在这里看到的是"哪个环节、哪个变量、HTTP 几号错误",而不是评测跑到一半一堆用例一起失败。

```bash
pnpm models:check                       # 全查:静态检查 + 每个环节真请求一次
pnpm models:check --stage judge         # 只查裁判;--stage 可以重复,如 --stage gate --stage actor
pnpm models:check --no-network          # 不发请求,只做静态检查(价格、快照),没有 Key 也能跑
pnpm models:check --strict              # 有警告也算不通过(上线前用;DeepSeek 那条是提示,不算)
pnpm models:check -v                    # 另外打出网关记下的原始日志(llm_calls 的一行)和模型回复
```

模型配置默认读 `config/models.yaml`,设了 `FDE_MODELS_CONFIG` 就读它指的文件(和 `pnpm evals`、`pnpm play` 一样)。

### 查什么

| 检查 | 不过时 | 说明 |
|---|---|---|
| Key 在不在 | 该环节**失败**,点名缺哪个环境变量 | 只显示"已配置 / 缺失",不打印 Key 的值;只有空白也算缺失。供应商报错、模型回复里回显的 Key 会被抹成 `***`:先整段抹再截断(回复预览截到 80 字,网关把报错正文截到 300 字),截断处残留的 8 个字符以上的 Key 片段也抹 |
| 真请求一次 | 该环节**失败** | 走 `@fde/llm` 网关,参数和线上完全一样(温度、`extra` 里的 `enable_thinking: false`、json 模式、`timeout_ms`),只把 `max_tokens` 压小:关了思考的环节 64,没关思考的(裁判)1024。不重试,看的是第一次请求的真实结果 |
| JSON 环节的回复 | 该环节**失败** | 闸门和裁判(引擎调用时固定开 json 模式)要求整段回复直接就能解析成 JSON 对象;文本环节(演员、复盘)要求回复不为空。这一条**故意比线上严**:引擎解析时会去掉 ` ```json ` 围栏、截取第一个 `{` 到最后一个 `}` 之间的部分,预检不放过这些,为的是确认 `json_object` 模式真的生效了 |
| 价格 | **失败** | 每个用到的模型都要在 `prices` 里有同名条目。没登记时网关把花费记成 `null`,`pnpm evals` / `calibrate` 汇总时按 ¥0 算,花费悄悄消失 |
| 百炼快照 | **警告** | 模型名不带日期后缀(`-YYYY-MM-DD`,更早的快照是 `-MMDD`)时提醒:这类名字会跟着上游升级。`-latest` 也算没固定 |
| DeepSeek | **提示**(不算警告) | DeepSeek 没有带日期的快照,旧模型名的请求会被转给新模型(方案 2.3、[S6]);提醒上游一有变动就重跑回归。不影响结论,`--strict` 也不因它失败(原因见下) |

每个发了请求的环节会打一行网关记下的数据:

```text
  ✓ gate    bailian/qwen3.7-flash     DASHSCOPE_API_KEY 已配置  JSON 对象回复 ✓
      耗时 … ms · 输入 … / 输出 … / 缓存 … token · ¥… · 尝试 1 次
```

静态检查的每一条前面标着级别:`✗` 失败、`!` 警告、`i` 提示。最后汇总本次预检的请求数和花费,给出结论。

### 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 都通过(可以有警告、提示) |
| 1 | 有检查没过;或 `--strict` 下有警告(提示不算) |
| 2 | 参数或配置错误:未知参数、未知环节、配置文件不存在或不合法 |

`--no-network` 下不发请求,Key 只列出有没有,**不计入结论**:没有 Key 的机器(比如 CI)也能用它检查配置本身。

**`--strict` 在当前配置下不通过**:闸门、演员、复盘的模型名都没带日期(三条快照警告),按第 3 节换成快照名、补上价格就能过。裁判在 DeepSeek 上那条是**提示**,不算警告,`--strict` 不因它失败:DeepSeek 没有快照可钉,配置里没有能改的地方,唯一能消掉它的办法是把裁判换到别家,又和方案"演员和裁判用不同厂商"的建议相悖;真正的对策是上游一变就重跑 `pnpm evals --live` 和 `pnpm calibrate --live`(见第 3 节)。所以 `--strict` 的意思是"能钉死的都钉死了"。

### 常见失败

| 看到 | 多半是 |
|---|---|
| `缺少环境变量 XXX` | `.env` 没建、变量名拼错,或等号后面是空的 |
| `401` / `403` | Key 错了、过期了、地域不对,或账号没开通这个模型 |
| `400` | 模型名不对,或 `extra` 里的参数(如 `enable_thinking`)这个模型不认 |
| `404` | `base_url` 或模型名不对 |
| `429` | 限流,或额度、余额用完 |
| `超时:N ms 内没有返回` | 网络慢或供应商卡住;N 是该环节的 `timeout_ms`(没配是 30000) |
| `网络错误 …… 连不上 <base_url>` | 断网、代理,或 `base_url` 写错 |
| `网络错误 …… 连上了,但返回的不是 JSON` | 请求到了,但对面回的是网页:`base_url` 指向了登录页、代理或别的网站 |
| `网络错误 …… Key 里有非法字符` | Key 里混进了全角字符或换行(多半是复制时带进来的),请求头都发不出去 |
| `回复不是合法 JSON(json 模式可能没生效)` | 这个模型不支持 `response_format: json_object`,或兼容层没生效;回复里连 `{…}` 都抠不出来,闸门和裁判上线会解析失败 |
| `回复不是纯 JSON(包了 ```json 围栏或夹了别的文字……)` | json 模式同样没生效,只是回复里还能抠出一个 JSON 对象:线上的解析能容忍,这次不会出错,但输出格式全凭模型自觉。预检照样判失败,先查模型支不支持 json 模式 |
| `回复为空;这个环节没关思考……` | 思考过程把 `max_tokens` 用完了;线上的上限大得多,一般不影响,但说明这个模型在思考 |

## 3. 固定快照(方案 2.3)

**为什么**:不带日期的模型名(稳定版名、`-latest`)背后的模型会被上游升级。演员的脾气、闸门的判断一变,回归评测和标定的结论就不再成立,而且没有任何报错。所以上线前要把模型名换成带日期的快照名,之后只在主动换模型时才变,每次变都跑一遍回归。`config/models.yaml` 里演员那行的注释说的就是这件事。

### 去哪找快照名

- **百炼控制台的模型广场**:点进某个模型的详情页,看它列出的版本。
- **阿里云帮助中心里百炼(Model Studio)文档的「模型列表」页**:每个模型分稳定版、最新版、快照版列出;快照版的名字是在模型名后面加日期,形如 `<模型名>-YYYY-MM-DD`(更早的快照是 `<模型名>-MMDD`)。

挑的时候:

- 如果列表注明了稳定版当前等同于哪个快照,优先选那一个:行为和现在跑回归时最接近。
- 看一眼这个快照有没有写下线时间;快要下线的不要选。
- 不是每个模型都有快照版。没有的话只能先留着稳定版名,预检会一直警告,`--strict` 也一直不通过(这条不像 DeepSeek 那样降成提示:百炼上能不能钉住取决于选哪个模型,配置里有得改);留着的期间按 DeepSeek 的办法处理(见下),上游一变就重跑回归。
- 快照名照官网原样抄,不要自己拼日期。

### 换完要做的

1. 只改 `config/models.yaml` 里对应环节的 `model`,别的参数不动。
2. 在 `prices` 里加一条同名的价格(元/百万 token,`[输入, 输出]`,照百炼价格页)。漏了的话 `pnpm models:check` 报失败,`pnpm test` 里也有一条检查仓库配置的每个模型都登记了价格。
3. `pnpm models:check`:确认快照名能调通、JSON 环节回的是 JSON、价格齐了。
4. `pnpm evals --live`:闸门和演员用真模型跑 10 个脚本化玩家,看闸门命中率,以及泄露、编造、出戏、附和这几类只有在线模式才有意义的断言。
5. `pnpm calibrate --live`:裁判标定(稳定性和人工一致性两道门槛,见 [`calibration.md`](./calibration.md))。裁判模型换了必须跑;只换演员时它测不到演员,但对局风格变了,下一批人工标注要用新对局。

### DeepSeek

DeepSeek 没有带日期的快照,旧模型名的请求会被转给新模型(方案 2.3、附录 F 的 [S6]),价格也会调(8 月的峰谷定价,[S7])。所以:

- 关注 DeepSeek API 文档里的模型与价格说明和更新公告;
- 上游一有模型或价格变动,就重跑 `pnpm evals --live`(裁判在 DeepSeek 上,所以还要 `pnpm calibrate --live`),并核对 `prices`;
- `pnpm models:check` 对 DeepSeek 的环节始终给一条**提示**(不是警告):不影响结论,`--strict` 也不因它失败。它没法靠改配置消掉——唯一的办法是换厂商,而方案建议演员和裁判用不同厂商——所以只当提醒:能做的就是上一条,上游一变就重跑回归。

## 4. 预检花多少钱

每个环节一次请求,提示词约 30–50 个输入 token,回复几个 token;`max_tokens` 封顶 64(裁判 1024)。按 `config/models.yaml` 里的标价:

| 环节 | 模型 | 价格(元/百万 token) | 通常 | 最坏(输出用满上限) |
|---|---|---|---|---|
| 闸门 | qwen3.7-flash | 0.2 / 0.8 | 约 ¥0.00002 | 约 ¥0.00006 |
| 演员 | qwen-plus | 0.8 / 2 | 约 ¥0.00005 | 约 ¥0.0002 |
| 裁判 | deepseek-v4-pro | 9 / 27(高峰价) | 不思考约 ¥0.0006;思考几百 token 约 ¥0.005–0.01 | 约 ¥0.03(1024 个输出 token) |
| 复盘 | qwen3.7-plus | 2 / 8 | 约 ¥0.0001 | 约 ¥0.0006 |

全量预检一次通常不到 ¥0.01,最坏约 ¥0.03,主要花在裁判上。实际花费以每次输出末尾"本次预检发了 N 次请求,约 ¥…"为准。

## 5. 和其他命令的关系

- `pnpm check` 和 `pnpm ci:local` **不跑**预检(CI 里没有 Key)。想在没 Key 的地方查配置,用 `pnpm models:check --no-network`。
- 预检只证明"能调通、参数被接受、价格齐、名字固定了",不证明模型好用。好不好用看 `pnpm evals --live` 和 `pnpm calibrate --live`。
- 命令行代码在 `apps/cli/src/models-check.ts`,检查逻辑在 `packages/llm/src/preflight.ts`,测试(本地假服务,不出网)在 `packages/llm/test/preflight.test.ts`。
